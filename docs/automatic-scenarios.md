# Automatic combat scenarios

During combat the HUD displays overlapping detected scenarios alongside the existing ready spell suggestions. All eleven checklist categories are represented: single target, cleave, AoE, PvP, kiting, healing, interrupts, burst, movement, utility and resource pressure. The current character's scenario checklist supplies the caution text; browsing another build does not change the live identity.

Engaged hostile target, focus, boss and nameplate units are counted once by GUID. One/two/three or more visible enemies select single/cleave/AoE; this is a minimum count, not proof that no other enemies exist. Idle nearby enemies are excluded. Area spell permission remains controlled by the rotation's AoE setting because detecting three enemies does not establish that breaking crowd control is safe.

Hostile players or PvP instances identify PvP. Readable increasing distance from an engaged enemy targeting the moving player identifies kiting. Movement alone identifies movement, not a specific boss mechanic. A friendly unit below 35% health identifies healing pressure. Interruptible engaged enemy casts identify interrupt windows. Ready dispel prompts identify utility windows. Mana below 20% identifies resource pressure; low rage is not treated as a mistake. Burst reflects a recognized active class cooldown effect (matched against the local Forever catalog IDs) or the player's explicit burst setting, rather than an invented automatic cooldown assignment.

The recorder stores scenario start/end events and up to 600 overlapping windows per fight. Each window includes its evidence, successful and failed player casts, matching targeted responses and client errors, with up to 80 detailed actions. Combat Review groups these results by scenario. Successful casts establish execution, not damage/healing effect or optimal selection. Interrupted casts and unconfirmed responses are investigation points, not automatic blame. Group members' casts do not count as the player's work. Scenario summaries persist with the ten saved reviews even after the five detailed timelines rotate out.

Exported fights include the same windows. The browser's Fight recording page displays each window and its action details. Runtime observations depend on readable client APIs; unavailable signals are omitted. Verify HUD placement and encounter observations in WoW; local tests use mocked client events.

Combat identity and learned abilities are captured for each fight. Browsing another guide does not change that identity. A non-healer's low-health window is reviewed as survival pressure; low-health allies do not create an automatic group-healing assignment for damage or tank roles. Rogue advice never assumes a healing spell. Defensive and interrupt names appear only when they were confirmed learned. Archived scenario reviews use the saved identity rather than whichever character or guide is selected now.

When the client cannot identify the actual specialization, select your current class/spec in Combat Review and press **Use this spec** to save a per-character fallback. A detected class cannot be replaced with another class, learned abilities are still checked, and automatic spec detection takes priority when it becomes available. The fallback does not spend or select talents.
